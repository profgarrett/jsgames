Watch it work

Boosting starts with one guess for every point, the average, and then repeats three steps. Errors finds how far off each prediction is. Small tree fits a tree to those errors. Add moves every prediction by a fraction of what the tree says.

Teacher notes

        
    
          
  • Each leaf predicts the average error of its points, so adding the tree moves each group toward its own average. Refitting the original data would just give the same tree again.
    • 
          
  • Trees split in different places. With depth 1, each tree adds at most one new jump, so after n trees the prediction has at most n + 1 levels. The sum of many small steps looks like a curve.
    • 
          
  • Training RMSE cannot go up when the learning rate is 1 or less: each leaf moves its points part of the way toward their average error. Whether that helps on new data is activity 3.
    • 
          
  • This page uses plain averages in the leaves (reg_lambda=0) to match the hand example in the lesson. XGBoost's default shrinks each leaf slightly. Activity 4 has that setting.
    • 
          
  • On Wavy line, learning rate 1 gets the RMSE to 0.53 in 10 trees. Learning rate 0.1 is still at 0.81 after 30.
    • 
          
  • Car weight and mpg is the lesson's data with one predictor. The first split lands at 2,765 lb, which is where a single tree would split too.

Teacher notes

        
    
          
  • With learning rate 1 each tree is added in full, so within a few trees the model starts fitting the scatter of individual training points. Its validation error bottoms out early and climbs.
    • 
          
  • With 0.1 each tree is a small nudge. The line stays smoother, the validation error bottoms out later and lower, and it climbs more slowly afterward.
    • 
          
  • Rule of thumb: learning rate and number of trees trade off. Halve one, roughly double the other.
    • 
          
  • Depth 6 makes both sides overfit much sooner: learning rate 1 is at its best after a single tree. Depth 1 lets learning rate 0.1 keep improving for well over 100 trees.
    • 
          
  • The lesson's car data shows the same pattern: with learning rate 0.3 the validation error was lowest after 7 trees, and with 0.05 it took 60.

When to stop

      
Training error always falls as trees are added. Validation error falls, levels off, and then rises. Early stopping watches the validation rows and stops once they have gone a set number of trees without improving.

Teacher notes

        
    
          
  • Training error can only fall, so it would say "never stop". Validation rows stand in for new data.
    • 
          
  • If the test rows chose the number of trees, the test score would be the best of many tries and would overstate how the model does on new data.
    • 
          
  • A small patience can stop at a temporary bump in a noisy validation line, before the real minimum. A large patience wastes time but finds the same model. With the settings the page opens with, 5, 10, 20 and 50 all keep the same model.
    • 
          
  • best_iteration counts from 0, so the number of trees kept is best_iteration + 1.
    • 
          
  • With a smaller learning rate the low point moves to the right (52 trees at 0.05 instead of 8 at 0.3). Here it is no lower, only later.

Teacher notes

        
    
          
  • The defaults (100 trees, 0.3, depth 6) reach a training RMSE of 0.01 and a validation RMSE of 1.67, which is worse than the single tree's 1.32. That gap is the overfitting signal, the same as R² of 1.0 against 0.74 in the lesson.
    • 
          
  • Early stopping matters most. The same defaults with early stopping keep only 4 trees and score 1.25. The best models, at about 1.10, use depth 3 with early stopping, and the learning rate hardly matters once early stopping picks the number of trees.
    • 
          
  • A larger reg_lambda shrinks every leaf toward zero. It helps a little: the default model improves from 1.67 to 1.57 with reg_lambda = 10.
    • 
          
  • The best model scores 1.09 on the validation rows and 1.12 on the test rows, against 1.28 for the single tree. The winner was picked because it scored well on these validation rows, so part of that score is luck. The test rows had no part in the choice, so they give the honest number. Checking them repeatedly would turn them into a second validation set.
    • 
          
  • The data is a made-up curve with noise. The noise has a standard deviation of 1.0, so no model can honestly get an RMSE much below 1.0 on new rows.

Forest or boosting

      
Two ways to combine many trees. A random forest grows deep trees separately, each on a random sample of the rows, and averages them. Boosting grows small trees in sequence, each one on the errors left so far.

    • 
        

      

      

        
Teacher notes

        
    
          
  • Forest trees are independent, so they can be built in parallel and more trees never hurt: the average just settles down. Its error falls quickly and then goes flat.
    • 
          
  • Boosting's trees depend on each other, so they are built in order. Its error falls for longer, often ends below the forest, and then turns up if you keep going. It is the one that needs early stopping.
    • 
          
  • A single deep tree memorizes its training rows. Averaging many of them cancels much of that noise (lower variance). Boosting starts with a model that is too simple and removes the error step by step (lower bias).
    • 
          
  • Boosting here uses learning rate 0.1 and depth 2. The forest uses unpruned trees on bootstrap samples, with a minimum of 3 rows per leaf.
    • 
          
  • Practical answer to the last question: forests are harder to get wrong, boosting usually wins when it is tuned and the dataset is large.

  • Where on the plot is the model least sure? Why there?
    •

    •

    • 
        

      

      

        
Teacher notes

        
    
          
  • Each tree's leaf moves the log-odds, not the probability directly, which is why the shading saturates smoothly instead of jumping to 0% or 100%.
    • 
          
  • Trees can only cut parallel to an axis, so a diagonal boundary becomes a staircase. Logistic regression gets that dataset with one line. It cannot do the ring or the crescents at all.
    • 
          
  • Depth 1 trees can only add up one-feature effects, with no "x is high AND y is low". That turns out to be enough for all four datasets here. It just takes more trees: about 50 for the crescents instead of 20.
    • 
          
  • On Overlapping groups the classes really do overlap, and even a perfect model would be right only about 77% of the time. Training accuracy climbs to 100% by drawing islands around single points, while validation accuracy stays near 65%. That is the classification version of activity 3.
    • 
          
  • Two crescents reaches 95% training accuracy at 12 trees with the settings the page opens with.
    • 
          
  • Changing the cutoff from 50% ties to the threshold and ROC discussion in the Predicting Categories lesson.
